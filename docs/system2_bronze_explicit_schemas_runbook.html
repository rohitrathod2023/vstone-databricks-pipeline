Bronze explicit schemas, replayed step by step

Replaces every implicit-schema read at Bronze (inferSchema, un-schema'd reads, COPY INTO's inferred CTAS, spark-xml sampling) with one explicit, permissive (all-StringType) schema per source — per Databricks' own medallion architecture guidance. Strict typing is Silver's job, not done here.

Resolves the same source_key indirection get_source_config() already handles (e.g. bronze_streets → raw_streets):

def get_source_schema(source_key: str):
    from config.schemas import SCHEMAS

    sources = _load_yaml(_SOURCES_FILE)
    if source_key not in sources:
        raise KeyError(f"No sources.yml entry for '{source_key}'. Known keys: {sorted(sources)}")

    lookup_key = sources[source_key].get("source_key", source_key)
    if lookup_key not in SCHEMAS:
        raise KeyError(
            f"No schema defined for '{lookup_key}' (resolved from '{source_key}'). Known: {sorted(SCHEMAS)}"
        )
    return SCHEMAS[lookup_key]

Add this right above the existing get_all_source_keys() function.

Edit io_readers.py — accept an optional explicit schema
edit src/common/io_readers.py

Replace read_csv/read_json/read_xml/read_source with schema-aware versions:

def read_csv(spark, path: str, schema=None, **options):
    reader = spark.read.format("csv").option("header", "true")
    reader = reader.schema(schema) if schema is not None else reader.option("inferSchema", "true")
    return reader.options(**options).load(path)


def read_json(spark, path: str, schema=None, **options):
    reader = spark.read.format("json")
    if schema is not None:
        reader = reader.schema(schema)
    return reader.options(**options).load(path)


def read_xml(spark, path: str, schema=None, **options):
    reader = spark.read.format("xml").option("rowTag", options.pop("rowTag", "record"))
    if schema is not None:
        reader = reader.schema(schema)
    return reader.options(**options).load(path)

And read_source:

def read_source(spark, source_config: dict, schema=None, **options):
    fmt = source_config["format"]
    if fmt not in READERS:
        raise ValueError(f"No reader registered for format '{fmt}'. Known: {sorted(READERS)}")
    return READERS[fmt](spark, source_config["path"], schema=schema, **options)

schema=None still falls back to inferSchema — kept for any future ad hoc read, but every Bronze/Day 1 source below always passes an explicit one.

Edit copy_into.py — explicit target-table DDL, drop inferSchema
COPY INTO's target table must already exist. The old version created it via a zero-row CTAS over read_files(..., inferSchema => true), which let the target's shape get inferred. Now it's a plain, explicit column list.
edit src/pipelines/bronze/copy_into.py
from common.config_loader import get_source_config, get_source_schema  # add get_source_schema

def build_create_table_sql(cfg: Dict[str, Any], source_key: str) -> str:
    target_table = cfg["target_table"]
    schema = get_source_schema(source_key)
    column_defs = ",\n            ".join(f"{f.name} STRING" for f in schema.fields)

    return f"""
        CREATE TABLE IF NOT EXISTS {target_table} (
            {column_defs},
            load_dt TIMESTAMP,
            source_format STRING,
            source_file STRING,
            run_id STRING
        )
        USING DELTA
    """.strip()

Note the signature change — source_key is now a required second argument. In build_copy_into_sql, remove 'inferSchema' = 'true' from FORMAT_OPTIONS (CSV defaults to all-string columns without it, which is exactly what we want):

FORMAT_OPTIONS ('header' = 'true', 'mergeSchema' = 'true')   # was: ..., 'inferSchema' = 'true', ...

And update the one call site in run_copy_into:

spark.sql(build_create_table_sql(cfg, source_key))   # was: build_create_table_sql(cfg)

4 Deploy and verify for real — including a required reset step
⚠️
This step is not optional. Your 8 Bronze tables already exist from earlier work, created back when the old code inferred column types (e.g. enter INT, date TIMESTAMP). CREATE TABLE IF NOT EXISTS is a no-op against a table that already exists — if you skip this, every column will silently stay whatever type it already was, and you won't be able to tell the fix actually worked. Confirm the current (wrong) types first if you want the "before" proof for your own documentation:

Merge — this auto-triggers a redeploy, not a rerun
.github/workflows/databricks-ci-cd.yml has a deploy-dev job that runs on every push to dev (which a merged PR produces) -- IF your repo has DATABRICKS_HOST/DATABRICKS_TOKEN secrets configured. It runs "databricks bundle deploy -t dev" automatically. It does NOT re-run the jobs themselves -- you already did that manually in Part 4, which is what actually matters for verification.

Merge the PR once CI is green. If your repo doesn't have those secrets set yet, the deploy-dev job will simply fail or be skipped — that's fine, since you already deployed and verified manually in Part 4 before opening the PR.
