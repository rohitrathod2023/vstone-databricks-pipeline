Day 2 Bronze COPY INTO — chunk1_csv + 4 raw files → 5 tables
1
Branch off dev
git checkout dev && git pull
git checkout -b feature/bronze-layer
2
Edit src/config/sources.yml
This is the "check this first" step — split all 4 chunk chunks onto their own Bronze tables before writing any pipeline code, and mark them as already carrying audit columns from Day 1's chunking output.
edit src/config/sources.yml

For each of chunk1_csv / chunk2_csv / chunk3_json / chunk4_xml, add one line and rename the target table:

  target_table: ${catalog}.${bronze_schema}.traffic_counts_copyinto   # _dlt / _autoloader / _pyspark for the other 3
  has_audit_columns: true

(has_audit_columns only matters to Day 2's COPY INTO technique — the other three chunks carrying it now is harmless prep for Day 3.)

3
Edit src/common/config_loader.py
Resolves the source_key: raw_streets-style indirection that bronze_streets/bronze_node_locations/bronze_streets_list/bronze_telegram use — without this, those 4 sources throw KeyError: 'path'.
edit src/common/config_loader.py

Copy the file from the ZIP over your local copy — the change is additive logic inside get_source_config(), no account-specific values involved.

4
Add two shared utilities
new src/common/metadata.py

Config-driven COMMENT ON TABLE, sourced from each entry's existing description in sources.yml.

new src/common/sanity_checks.py

Row-count + non-null-audit-column gate, run after every Bronze load.

5
Add the COPY INTO pipeline module
new src/pipelines/bronze/__init__.py

Empty file — just makes bronze a package.

new src/pipelines/bronze/copy_into.py

One generic run_copy_into(spark, source_key, env), reused for all 5 Day 2 sources.

6
Add the notebook + job resource
new src/notebooks/02_bronze_copy_into.py
new resources/jobs/bronze_copy_into_job.yml

One job, 5 parallel tasks, same notebook, different source_key each time.

7
Add the test file, then run local checks
new tests/unit/test_copy_into.py
flake8 src tests --max-line-length=120
pytest tests/unit -v

Day 3 Auto Loader + PySpark + DLT — chunk2/3/4 → 3 more tables
1
Edit databricks.yml — one line
Without this, the DLT pipeline resource silently won't deploy at all.
edit databricks.yml

Add one line to include: — don't copy the whole file, yours has your own workspace host:

include:
  - resources/jobs/*.yml
  - resources/pipelines/*.yml   # add this line
  - resources/*.yml
2
Edit setup.cfg — one line
The DLT source file uses Databricks-injected globals (spark) the same way notebooks do, but lives outside src/notebooks/.
edit setup.cfg
exclude = .git,__pycache__,src/notebooks,src/pipelines/bronze/dlt_traffic_counts.py
3
Add the Auto Loader pipeline module
new src/pipelines/bronze/autoloader_ingest.py

Loads chunk3.json via its exact file path, not the shared chunks/ directory + a glob filter — the filter option proved unreliable on this runtime the first time around.

4
Add the PySpark XML pipeline module
new src/pipelines/bronze/pyspark_xml_ingest.py

Column-name sanitizing + explicit mode="overwrite" idempotency (this technique has no built-in rerun-safety of its own).

5
Add the DLT pipeline source
new src/pipelines/bronze/dlt_traffic_counts.py

Uses @dlt.expect for its own data-quality checks — deliberately not common.sanity_checks.

6
Add the two notebook entrypoints
new src/notebooks/03_bronze_autoloader.py
new src/notebooks/04_bronze_pyspark_xml.py
7
Add the DLT pipeline resource
new resources/pipelines/bronze_dlt_pipeline.yml

Uses ${resources.schemas.bronze_schema.name} for its target schema — DABs resolves that to your real mode-prefixed schema name at deploy time. Already confirmed working, nothing to adjust here.

8
Add the combined job resource
new resources/jobs/bronze_autoloader_pyspark_dlt_job.yml

One job, 3 tasks: Auto Loader, PySpark XML, and a pipeline_task triggering the DLT pipeline above.
