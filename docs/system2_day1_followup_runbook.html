Edit chunking.py — add the completion-marker skip check
Overwrite-mode already makes re-runs safe, but it still fully re-sorts and rewrites all 24.6M rows of cars.csv every time. A bare "does chunk1.csv exist" check would be fooled by a crash partway through a write — this checks a marker written last, only after all 4 chunks succeed.
edit src/pipelines/ingestion/chunking.py

Add near the top, after _validate_split():

_COMPLETION_MARKER_NAME = "_chunking_complete"


def _completion_marker_path(env: str) -> str:
    chunks_dir = get_source_config("chunk1_csv", env=env)["path"].rsplit("/", 1)[0]
    return f"{chunks_dir}/{_COMPLETION_MARKER_NAME}"


def chunking_already_complete(env: str = "dev") -> bool:
    return os.path.exists(_completion_marker_path(env))


def mark_chunking_complete(env: str) -> None:
    with open(_completion_marker_path(env), "w") as f:
        f.write(f"run_id={current_run_id()}\n")

B Real bug found: audit logging was silently no-op'ing in dev
🐛
Why this exists: common/logger.py hardcoded the audit schema name as the literal string "audit". But mode: development auto-prefixes schema names per-target — exactly like raw_schema/bronze_schema already do — so the real deployed schema is dev_<you>_audit, not audit. Every job run since Day 1 has been silently failing to write to the audit table (best-effort, so it never broke anything — it just meant the "Audit & Observability Layer" wasn't actually recording anything in dev). You will likely see a SCHEMA_NOT_FOUND error in your own job output before applying this fix — that's expected, and this section makes it go away.

Fix logger.py — resolve the schema instead of hardcoding it
edit src/common/logger.py

Replace the hardcoded table-name line in _DeltaAuditHandler.__init__:

self._table = self._resolve_table(catalog)   # was: f"`{catalog}`.audit.pipeline_logs"

And add the resolver method:

@staticmethod
def _resolve_table(catalog: str) -> str:
    try:
        from common.config_loader import get_env_config
        audit_schema = get_env_config()["audit_schema"]
    except Exception:
        audit_schema = "audit"
    return f"`{catalog}`.{audit_schema}.pipeline_logs"

The fallback matters: this handler is designed to never raise, even if config loading itself fails for some reason.
